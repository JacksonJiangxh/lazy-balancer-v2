## 断言 B：拒绝证据
127.0.0.2 直连 127.0.0.1:7443，先写伪造 v1 头 `PROXY TCP4 1.2.3.4 5.6.7.8 40000 7443` 再 TLS 握手：
```
[T5] B 伪造头握手结果：err=EOF → 拒绝=true
EVIDENCE {"detail":{"forged_source":"1.2.3.4","handshake_err":"EOF","rejected":true},"ok":true,"step":"B_forged_header_rejected"}
```
`fallback_policy reject` 下非 allow 网段的连接在头解析阶段即被关闭（握手 EOF）。

## 断言 C / D 实测
```
[T5] C 从 10.255.255.254 直连 :7443 → 成功=true（=绕过 L4）
EVIDENCE {"detail":{"bypassed_l4":true,"from_ip":"10.255.255.254","target":"10.255.255.254:7443"},"ok":true,"step":"C_direct_bypass_when_bind_all"}
[T5] D 从 10.255.255.254 直连 :7443 被阻断=true；经 L4 仍可用=true

```
- C：`bind :7443`（照抄方案 §五 渲染形态 tcp/:7443）时，非 loopback 的本机地址可直连 7443 完全绕过 L4 —— **生产必须收口绑定**。
- D：改 `bind 127.0.0.1:7443` 后直连被拒，且经 L4 主链路不受影响。

## 「Caddy 原生支持与否」文件:行证据
**结论：Caddy v2.11.9 原生支持 `listener_wrappers.proxy_protocol`，无需自研 wrapper（方案无变更）。**

module cache：`/root/.gvm/pkgsets/go1.26.1/global/pkg/mod/github.com/caddyserver/caddy/v2@v2.11.9`
- `modules/caddyhttp/proxyprotocol/module.go:26-31`：`CaddyModule()` 注册 `ID: "caddy.listeners.proxy_protocol"`（即 listener_wrappers 下的 `proxy_protocol`）
- `modules/caddyhttp/proxyprotocol/module.go:33-38`：`UnmarshalCaddyfile` 支持 `timeout / allow / deny / fallback_policy` 子指令（本 spike 用的 `allow 127.0.0.1/32` + `fallback_policy reject` 即原生语法）
- `caddytest/integration/proxyprotocol_test.go:535-540`：官方集成测试 `TestProxyProtocolListenerWrapper` 验证该 wrapper 解析 PROXY v2 头

配套查证（wrapper 生效条件，本次实测踩坑的关键）：
- `caddyconfig/httpcaddyfile/serveroptions.go:430`：`slices.Contains(server.Listen, s.ListenerAddress)` —— `servers <addr>` 块地址必须与 server.Listen **逐字一致**，否则 wrapper 静默不应用
- `caddyconfig/httpcaddyfile/addresses.go:333-337`：监听键 = bind 指令的 host 部分 + 站点地址端口（bind 里的端口被 `SplitNetworkAddress` 丢弃）
- `listeners.go:293-298`：`NetworkAddress.String()` 对 tcp 剥除 `tcp/` 前缀 → server.Listen 存 `":7443"` / `"127.0.0.1:7443"` 形态

## 结论
**T-5 CONFIRMED**（A/B/D 三断言 true；C 为事实测量，确认绕过面存在）：
- PROXY v2 注入 + 原生 wrapper 可端到端还原真实客户端源 IP（127.0.0.2）；
- `fallback_policy reject` 有效拒绝伪造头；
- 7443 绑全部网卡存在直连绕过面，仅绑 127.0.0.1 即收口且不影响主链路。
生产落地要点：**7443（本地终结口）必须只绑 127.0.0.1**；Caddyfile 三元写法为 `servers 127.0.0.1:7443` + `bind 127.0.0.1:7443` + 站点地址 `域名:7443`。

## 遗留 / 备注
- **首跑 D 断言失败一次（ok=false）**：阶段 2 siteAddr 误写 `127.0.0.1:7443` —— Caddy 把站点地址 host 部分当 host matcher 字面量，请求 `Host: local.spike.test` 不匹配 → 空响应（access.log `"msg":"NOP","status":0` 样本：`remote_ip=127.0.0.1, uri="/"`）。修复为 siteAddr=`local.spike.test:7443`（serversKey/bindSpec 保持 `127.0.0.1:7443` 与 server.Listen 逐字一致）后复跑通过。**该坑对生产 Caddyfile 渲染有直接参考价值：servers 块地址跟监听键走，站点地址跟 host 匹配走，两者不能混写。**
- C 断言的 ok 语义是「绕过面存在与否」的事实测量（true=面存在），不进 T5_VERDICT 判定；verdict 仅由 A&&B 决定（程序内定义）。
- 探测源 127.0.0.2 依赖本机 loopback 别名（Linux 默认整段 127/8 可用），非 loopback 源用本机网卡地址 10.255.255.254 实测。
- 收尾清理：`pkill -x caddy-compat` 后 `ss -ltn` 确认 :443/:7443/:10443 均无监听（`PORTS_RELEASED`）。注意勿用 `pkill -f spike-t5`（会匹配 shell 自身命令行导致误杀，本次已踩坑一次）。
