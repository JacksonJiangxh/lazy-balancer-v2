## [卡-20261110-01] 假追平识别法：以 merge-tree 树为骨 + 逐路径存在性核对
- 症状：上一轮 v2.3.8「追平」后 main 仅 875 文件，上游 1694，业务域取我们侧旧实现整批丢失上游新增文件。
- 根因：merge-base 选择错误（无共同祖先重写史）+「按域取我们侧完整实现」，无机械存在性核对。
- 判据：`git merge-tree --write-tree --merge-base=<真实共同祖先> main <tag>` 产出树；`git ls-tree -r --name-only <tag>` 逐路径核对 MISSING 必须为 0。
- 解法：本轮 `git replace --graft 0cd475ed 9c759716` 桥接 merge-base，merge-tree 得 87 冲突/树 9e50f1ef；A4 逐路径核对 2095/2095；见 commit bb05ecda。
- 适用条件／不适用面：适用于「历史被重写、tag 与 fork 无共同祖先」的上游追平；不适用 tag 本身缺失或对象库无 tag 树的场景。
- 复发：首次（上次为 ffb394d3/272970aa 假追平，负证据已登记）。

## [卡-20261110-02] 抢先实现文件的语义合并法：声明级可并集，函数级必须上游为骨+逐函数挂回
- 症状：69 个「两边独立实现同需求」冲突块机械取并集后，8 个文件 gofmt 报 `expected '('`（db.go/caddy.go 函数体被各取一半，括号失衡）；go vet 12 处 undefined。
- 根因：上游对 db.go(+4968)/caddy.go(+3248) 做函数级重构，「同需求两实现」落在同一函数粒度，文本并集破坏语法与结构。
- 判据：`gofmt -e <file>` 全量扫描（退码≠0 即结构破坏）；`go vet ./...` undefined 符号清单 = 未接线补丁的客观证据。
- 解法：声明级（列清单/字段/import）取并集去重；函数级恢复上游完整版为骨，逐函数读上游新结构后把补丁（4 列登记 newColumnsRegistry / buildChainProxyConfig 渲染链 / ResolveReferencedCertPath / 端口换位）挂回，并用 B5 钉测 + 存量库冒烟验证「功能对」。三路材料留 /tmp/p2src/、/tmp/selfblocks/ALL.txt。
- 适用条件／不适用面：适用于上游结构性重构 + fork 有增量补丁的合并；不适用「编译过即当功能对」——必须钉测+存量库冒烟。
- 复发：首次（本轮实测证伪「纯并集」捷径）。

## [卡-20261111-01] 存量库冒烟三步法：先对语义再造数据，孤儿清理是验收面不是事故
- 症状：冒烟 fixture 把 path_rules.rule_id 填成 lb_rules.id 数字 1，新版启动「孤儿清理 1 条」被疑为误删存量。
- 根因：v2.3.6 起 path_rules/upstreams 的 rule_id 语义就是「引用 lb_rules.caddy_id（VARCHAR）」而非行 id；造数前未读旧版 schema 的 FOREIGN KEY 声明。
- 判据：造 fixture 前先 `git show <旧版>:internal/db/db.go | grep REFERENCES` 对齐外键语义；清理类启动迁移必须与旧版同谓词对照（旧版 db.go 同样有 NOT IN (SELECT caddy_id …) 清理），「删了对的」也是验收证据。
- 解法：fixture 按旧版语义重造后二次启动，孤儿清理只剩真孤儿、存量数据全项无损；worktree 临时构建 + -config 独立 data_dir，全程不触共享目录。
- 适用条件／不适用面：适用于跨版本 DB 迁移冒烟；不适用无外键语义的纯 KV 库。
- 复发：首次。

## [卡-20261111-02] 修守卫红只是第一层：被前置门拦住的门禁链，后面每层都是未知盲区
- 症状：r3 按裁决修完守卫豁免后，test-all --fast 依次撞出两段从未被报告过的红——模块清单 drift（基线 6 vs 实际 7，缺 caddychain）与 gofmt 未收口 5 文件；风控官/r2 从未见过它们，因为审计守卫永远是第一道门，一红全链止步。
- 根因：门禁链的「前置短路」让下游门的缺口在多轮里持续隐身；各方核验报告只覆盖到第一失败点，误把「守卫红」当成 D3 的唯一缺口。
- 判据：修复任何前置门后，必须把整条链重跑到第一个新红点，直到 exit 0 为止；「修好了 A」≠「链路绿」。
- 解法：本轮逐层收口（守卫豁免 → 模块基线显式确认 → gofmt -w 机械收口）并在干净树复跑全链 exit 0；gofmt 类机械缺口用 -w 收口而非改门禁判据。
- 适用条件／不适用面：适用于多级 fail-fast 门禁链的修复轮；不适用单门场景。另记：沙箱 /app/logs 属实时运行数据，测试隔离缺陷导致的基线失败不可用「清环境」假修复。
- 复发：首次。
