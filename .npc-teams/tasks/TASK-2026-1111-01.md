### 2.2 静态响应双实现差异（实测数字）

| 维度 | 自研 `action='respond'` | 上游 `response_mode` 三值 |
|---|---|---|

### 7.6 经验卡
```
## [卡-20261111-03] 校验强度提回自研口径时，渲染侧必须同批改——只改校验会让 3xx 变成空重定向
- 症状：放开 static 模式 3xx 后，若只扩白名单不改渲染，选 301 的路径规则发出的响应没有 Location 头（静默变成「空重定向」），浏览器停在本页。
- 根因：上游 buildStaticResponseHandler 恒写 status_code + Content-Type + body，不看状态码分派；白名单只管「能不能存」，渲染侧管「发出去长什么样」，两者是两条独立代码路径。
- 判据：`go test ./internal/services/ -run TestPathRuleRoute_staticMode3xxRendersLocationNoBody` —— 断言 3xx 必须带 Location 且**无 body 无 Content-Type**；任一缺失即红。204 同理（禁体禁 CT）。
- 解法：白名单扩容与渲染侧按状态码分派必须同批改（本轮 `services.buildStaticResponseHandler` + `StaticResponseBodyAllowed` 单源判定）。见 commit 待填。
- 适用条件／不适用面：适用于「放宽白名单即有实际行为后果」的枚举类校验；不适用于纯文案/enum 一致性（那类只改校验侧即可）。
- 复发：首次。
```
