## §0 需求的专业化重述（总经理给董事长的对齐稿）

> **董事长的真实诉求（一句话）**：把「每次上游发版后手工追平」这件事，从**依赖人的经验**变成**依赖可复现的资产 + 标准流程**。

拆成三个可交付物：

| # | 交付物 | 解决的痛点 | 形态 |
|---|---|---|---|
| **O1** | **可复现差异清单** | 「我们到底改了上游什么」说不清、说不全，每次追平靠回忆 | 机器可复现的清单（脚本 + 数据文件）：给定「上游某版本」与「我们的 fork」，一条命令吐出全部差异，可 diff、可审计、可移植 |
| **O2** | **最小化改造基线** | 我们的改动量偏大，每次追平冲突面大、成本高 | 在等价功能前提下压缩改动面（减少侵入点、减少与上游同行改动的重叠），测试通过后作为新基线 |

**为什么这三件事必须一起做**：O1 是「账本」（知道改了什么），O2 是「减债」（让账本变薄），O3 是「流程」（让下次照账本做）。只做 O1 = 账本厚但流程还是靠人；只做 O3 = 有流程但不知道要合什么。

## §3 方案

### 3.1 三阶段依赖关系

```
O2（分析+可能改造）
   ↓ 若改造执行 → 重跑 O1 得到新清单
O1（差异清单脚本+产物）  ←──────┘
   ↓

   ↓
O3-6 实操演练（验证手册可执行）
```

**实际执行顺序**：先 O1（脚本是 O2/O3 的度量工具）→ O2（用它度量压缩效果）→ O3（引用两者）。

### 3.2 O1 设计要点

- **脚本**：`scripts/fork-diff.sh <base-ref> <target-ref> [--out-dir] [--check]`
- **归类的机械判据**（避免人工贴标签）：
  - 路径命中 `docs/self-developed-features.zh-CN.md` 的符号表所在文件 → 归属对应第 N 项
  - 路径在 `^(caddychain|internal/services/default_ports)` 等自研模块白名单 → 自研本体
  - 路径在 `^(\.npc-teams|docs|AGENTS|\.cnb|\.github|scripts/gate)` → 基建文档
  - 其余 → 待归类（必须逐条给结论，O1-5）
- **`upstream_also_touched` 字段**：给定 base 与「上游下一版本 ref」（可选参数），标出该路径在上游侧是否也被改动——**这是冲突预判的核心字段**

### 3.3 O2 优化方向（三条假设，须验证）

| 假设 | 做法 | 预期收益 | 风险 |
|---|---|---|---|
| **H1 注释外置** | 长解释注释（≥3 行）迁到 `docs/` 对应文档，代码内留 `// 详见 docs/xxx.md §N` 一行 | 减 ~400 行增量，降低同行冲突率 | 知识可发现性下降（须在手册中给出查找路径） |
| **H2 挂点收敛** | 与上游同文件的补丁，从「多处小改」改为「单点入口 + 内部实现」（如 caddy.go 的渲染分派抽成自研子函数，上游函数只留一行调用） | 减少冲突块数量 | 若上游重构该函数仍会冲突，但只冲突 1 处而非多处 |
| **H3 常量/配置外置** | 硬编码在 `caddy.go` 等的自研常量，收进独立文件/包 | 新建文件上游不动则不冲突 | 增加一文件 |

**每项假设都必须给出「改造前 vs 改造后」的量化对比 + 逐字节等价证明**，不成立的假设要如实记录为「已验证无收益」。

### 7.4 遇到的问题（踩坑与解法）

| # | 问题 | 根因 | 解法 |
|---|---|---|---|
| 1 | 脚本第一版 `build_records` 报一串 `command not found: awk/sort/grep` | 本环境对 `cmd \| while read` 与「外命令 stderr 重定向进 file」形态偶发拒跑 | 改为单次 awk 程序完成全部拼装；比较改用命令替换取 diff 全文；关键命令用绝对路径 |
| 2 | mawk 下 `match()` 的 `RSTART/RLENGTH` 按**字节**计 → 中文标题被切碎成乱码 | mawk 1.3.4 + UTF-8 locale 的多字节索引行为 | 先 `match` 取片段再在片段内抽数字 |
| 3 | `split(s, arr, "\u0060")` 对含中文的行**静默返回 1 段**（丢掉全部 token） | mawk 对多字节行 + 反引号分隔符的 split 实现缺陷 | 改 `index()/substr()` 手搓；并写下「不用 split/match 抽反引号」的注释纪律 |
| 4 | 归属一度全是 `none` | 登记文件的「代码位置」条目是**标题行 + 缩进子行**两行结构，聚合器只吃了标题行 | 加 `inblock` 状态机：命中条目行后，其缩进子行一并纳入 |
| 5 | `--help` 报 `awk: cannot open "usage"` | 本环境函数内 `$0` 解析成函数名 | 文件顶部 `SELF=${BASH_SOURCE[0]:-$0}` |
| 6 | `gate.sh` 报 `read-only variable: modules` | 父 shell 导出了同名只读变量 | 演练时 `env -u modules bash scripts/gate.sh`；gate.sh 不属本轮白名单，记 follow-up |

## [卡-20261111-08] 归属判定类脚本的三重静默陷阱：subshell 丢环境 / mawk 字节索引 / split 多字节失效
- 症状：fork-diff.sh 首版跑出「92 个差异路径但 0 条记录」；修一版后归属全为 none；再修后中文标题变乱码。
- 根因：① `cmd | while read` 与「外命令 stderr 重定向进 file」在本环境会被 ShellCheck 式防护机制拒跑
        （报 command not found 但退出码仍 0，静默错）；② mawk 1.3.4 在 UTF-8 locale 下
        `match()` 的 RSTART/RLENGTH 按字节计，`split(s,arr,"`")` 对多字节行只返回 1 段。
- 判据：脚本产出「文件数 > 0 但记录数 = 0」＝管道/子 shell 问题；归属全 none 但登记文件有内容＝
        解析器没吃到 token（用 `wc -l` 数中间表行数定位）；中文变乱码＝字节/字符索引混用。
- 解法：全部计算收敛到单个 awk 程序（不再用 `| while read`）；抽 token 用 `index()/substr()` 手搓，
        禁用 `split`/`match` 处理含中文的行；命令行工具用绝对路径（`$BASE_BIN/awk`）并集中声明依赖。

- 适用条件／不适用面：凡「解析中文文档 + 生成结构化清单」的脚本都适用；
        不适用纯 awk one-liner（不涉及多字节切分时无此坑）。
