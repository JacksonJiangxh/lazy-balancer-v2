## §0 需求的专业化重述（总经理给董事长的对齐稿）

> **董事长的真实诉求（一句话）**：把「每次上游发版后手工追平」这件事，从**依赖人的经验**变成**依赖可复现的资产 + 标准流程**。

拆成三个可交付物：

| # | 交付物 | 解决的痛点 | 形态 |
|---|---|---|---|
| **O1** | **可复现差异清单** | 「我们到底改了上游什么」说不清、说不全，每次追平靠回忆 | 机器可复现的清单（脚本 + 数据文件）：给定「上游某版本」与「我们的 fork」，一条命令吐出全部差异，可 diff、可审计、可移植 |
| **O2** | **最小化改造基线** | 我们的改动量偏大，每次追平冲突面大、成本高 | 在等价功能前提下压缩改动面（减少侵入点、减少与上游同行改动的重叠），测试通过后作为新基线 |

## §3 方案

### 3.1 三阶段依赖关系

```
O2（分析+可能改造）
   ↓ 若改造执行 → 重跑 O1 得到新清单
O1（差异清单脚本+产物）  ←──────┘

   ↓

```

**实际执行顺序**：先 O1（脚本是 O2/O3 的度量工具）→ O2（用它度量压缩效果）→ O3（引用两者）。

### 3.2 O1 设计要点

- **脚本**：`scripts/fork-diff.sh <base-ref> <target-ref> [--out-dir] [--check]`
- **归类的机械判据**（避免人工贴标签）：
  - 路径命中 `docs/self-developed-features.zh-CN.md` 的符号表所在文件 → 归属对应第 N 项
  - 路径在 `^(caddychain|internal/services/default_ports)` 等自研模块白名单 → 自研本体
  - 路径在 `^(\.npc-teams|docs|AGENTS|\.cnb|\.github|scripts/gate)` → 基建文档
  - 其余 → 待归类（必须逐条给结论，O1-5）
- **`upstream_also_touched` 字段**：给定 base 与「上游下一版本 ref」（可选参数），标出该路径在上游侧是否也被改动——**这是冲突预判的核心字段**

### 3.3 O2 优化方向（三条假设，须验证）

| 假设 | 做法 | 预期收益 | 风险 |
|---|---|---|---|
| **H1 注释外置** | 长解释注释（≥3 行）迁到 `docs/` 对应文档，代码内留 `// 详见 docs/xxx.md §N` 一行 | 减 ~400 行增量，降低同行冲突率 | 知识可发现性下降（须在手册中给出查找路径） |
| **H2 挂点收敛** | 与上游同文件的补丁，从「多处小改」改为「单点入口 + 内部实现」（如 caddy.go 的渲染分派抽成自研子函数，上游函数只留一行调用） | 减少冲突块数量 | 若上游重构该函数仍会冲突，但只冲突 1 处而非多处 |
| **H3 常量/配置外置** | 硬编码在 `caddy.go` 等的自研常量，收进独立文件/包 | 新建文件上游不动则不冲突 | 增加一文件 |

**每项假设都必须给出「改造前 vs 改造后」的量化对比 + 逐字节等价证明**，不成立的假设要如实记录为「已验证无收益」。

### 7.4 遇到的问题（踩坑与解法）

| # | 问题 | 根因 | 解法 |

| 1 | 脚本第一版 `build_records` 报一串 `command not found: awk/sort/grep` | 本环境对 `cmd \| while read` 与「外命令 stderr 重定向进 file」形态偶发拒跑 | 改为单次 awk 程序完成全部拼装；比较改用命令替换取 diff 全文；关键命令用绝对路径 |

```
## [卡-20261111-11] 注释外置只减「文本体量」，不减「侵入位置」——hunk 数不会降
- 症状：按计划把 59 个 ≥3 行注释块外置（393 行 → 18 行锚点，−95%），但 git diff 的 hunk 数
        几乎不动（126 → 125）。原报告的「hunk 163→95」预测落空。
- 根因：外置改的是「一个 hunk 内的行数」；hunk 数量由「补丁落在几个位置」决定，与外置无关。
        真正影响 hunk 数的是「把多处小改收敛成单点入口」（即 H2 那类改造），而 H2 也因收益仅 2–3% 被否。

        前者靠外置，后者靠收敛，两者收益不可混算。
- 解法：外置仍值得做（合 20 行注释远比合 2 行锚点费神），但**对外口径要改成「合并成本下降」**，

- 适用条件／不适用面：凡「注释/文档外置类」重构都适用；不适用「挂点收敛类」改造（那才真能减 hunk）。
- 复发：首次（是对 r1 报告 §2.3 预测的一次自我纠错）
```

```
## [卡-20261111-12] 汇编等价必须「剥离行号 + 过滤 rodata」，否则 100% 假红
- 症状：`go build -gcflags='-S'` 前后直接 sha256 比对，差异 192 行，看似「注释影响编译」；
        若不追查就会误判「外置改变了行为」，或反过来直接跳过证据链①。
- 根因：`-S` 输出每行都带 `(绝对路径:行号)`；且 .rodata 段以 hexdump 形式内嵌文件名/行号表
        （随行号偏移变化）。二者都与机器指令无关。
- 判据：剥离 `(/path:line)` 后仍有差异 → 再过滤 `^[[:space:]]+0x[0-9a-f]+ [0-9a-f]{2} ` 形态的 hexdump 行；
        两次过滤后差为 0，即为「指令部分等价」。
- 解法：`diff <(sed -E 's#\(\/[^)]*\)##g' a | grep -vE '^[[:space:]]+0x[0-9a-f]+ [0-9a-f]{2} ') <(同上 b)`。
        注意 `sed -E` 里 \t 不匹配制表符，用 `\(\/[^)]*\)` 直接匹配括号内容。
- 适用条件／不适用面：适用「纯注释/格式变更」的等价证明；**不适用**会真改代码的改造（那时差异应为非 0）。
- 复发：首次
```

```
## [卡-20261111-13] 本环境 `bash` 是 zsh 别名——脚本要双兼容，且用 /bin/bash 跑
- 症状：`bash scripts/check-doc-anchors.sh` 报 `command not found: mapfile`、
        `files[@]: parameter not set`；而文件头写的是 `#!/bin/bash`。
- 根因：`type bash` → `alias bash=zsh`。**显式调用 `bash x.sh` 会走别名进 zsh**，
        于是 bash 特有内建（mapfile、declare -A、数组展开差异）全部失效；真实 bash 在 /bin/bash。
- 判据：脚本里用了 mapfile / declare -A / 依赖未加引号变量词分割 → 本环境必炸或静默空转
        （zsh 默认不对未加引号变量做词分割）。
- 解法：① 避开 bash-only 内建（命令替换代替 mapfile，字符串代替关联数组）；
        ② 需要 bash 语义时显式 `/bin/bash script.sh`；
        ③ 传多文件给 for 循环用数组语法或 `/bin/bash -c` 包裹。
- 适用条件／不适用面：本环境（IDE/CLI 模式 zsh 默认）全部 shell 脚本；
        不适用「已确认可跑」的既有 gate.sh（它 `#!/bin/bash` 且直接执行时不走别名）。
- 复发：同族见 卡-20261111-09（`$0` 在函数内解析成函数名）——都是「本环境 shell 与常规 bash 有差异」
```
