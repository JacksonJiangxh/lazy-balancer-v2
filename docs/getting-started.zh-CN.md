# 快速开始（从零到跑起来）

> 面向「不懂 Go/前端、只想把服务跑起来」的读者：从一条命令到建好第一条反向代理规则，全程面板点选，不需要写代码。挂载目录、环境变量等参数细节见[部署指南](deployment.zh-CN.md)。

## 你需要准备什么（前置要求）

- 一台 **Linux** 机器，装好 Docker（host 网络模式仅推荐 Linux 宿主）。
- **80 / 443 端口未被占用**——这两个口给代理流量用，管理面板用 8000。
- 防火墙/安全组放行 **8000**（管理面板）、**80/443**（HTTP/HTTPS 代理流量；443 还要放行 UDP，HTTP/3 需要）。
- 一个 DNS 已解析到这台服务器的域名（第三步建规则、第五步验证要用；只想先看看面板可跳过）。

> **Windows/macOS 用户**：请用 Docker Desktop 的 bridge 模式（`-p 8000:8000 -p 80:80 -p 443:443 -p 443:443/udp` 端口映射），并把 `/app/data` 放在 named volume（`lb-data`）——bind mount 经 FUSE 共享层有 SQLite WAL 丢页风险（Linux 宿主 bind mount 无此问题）。完整命令见 [README](../README.md) 的「Docker Desktop」小节；仓库 `docker-compose.yml` 的主节点固定 host 网络，仅适用于 Linux。

## 第一步 · 启动服务（一条命令）

```bash
docker run -d --name lazy-balancer --network host \
  --restart unless-stopped \
  --pids-limit=4096 \
  --ulimit nproc=4096:4096 \
  --ulimit nofile=1048576:1048576 \
  --stop-timeout 30 \
  -v $(pwd)/data:/app/data -v $(pwd)/certs:/app/certs \
  -v $(pwd)/logs:/app/logs -v $(pwd)/waf:/app/waf \
  -v $(pwd)/backup:/app/backup \
  v55448330/lazy-balancer-v2:latest
```

> `--stop-timeout 30` 是停止宽限期：面板的优雅关停链最多花 25 秒（在途请求排水、Caddy 排水、日志刷盘等），而 Docker 默认只给 10 秒就强杀，所以示例带这个参数；自建 systemd/k8s 编排时也请保证停止宽限 ≥25 秒。

启动后容器会自动拉起管理面板与内置 Caddy。数据都落在上面挂载的目录里：`data`（数据库与配置）、`certs`（证书）、`backup`（自动备份）必选，`logs`、`waf` 推荐——容器重建后配置不丢。

## 第二步 · 初始化面板

1. 浏览器打开 `http://<你的服务器IP>:8000`。
2. 首次访问会进入初始化向导——**系统没有默认账号密码**，第一次访问由你创建管理员：
   - 用户名：小写英文开头，只允许小写字母和数字；
   - 密码：8-24 位（数字、大小写字母、特殊字符）。
3. 创建后自动登录，进入管理面板。

## 第三步 · 建第一条反代规则

进入「负载均衡」页，点「新建规则」，向导按步骤走（未启用的步骤会自动跳过）：

1. **基本配置**：
   - 规则名称：随便起，例如「我的网站」；
   - 协议：选 **HTTP**；
   - 域名：填你的域名，多个用英文逗号分隔（同时用于 HTTPS 证书和 HTTP→HTTPS 重定向）；
   - 监听端口：默认跟随部署 HTTP 默认口（80）；启用 HTTPS 后建议用部署 HTTPS 默认口（443）。管理端口（8000/2019）不可用，也不能与已有 TCP 规则同口；
   - 启用 HTTPS：打开后向导会多出「TLS 配置」步骤。证书来源三选一：手动上传 / **ACME + DNS 自动**（免费证书，DNS-01 验证、自动续签；需先在「系统设置 / 免费证书」添加 DNS 提供商配置）/ 引用证书文件（放 `/app/certs` 目录，外部更新文件后自动同步重载）；
   - 描述、访问日志：选填（访问日志开启后可在规则行点「日志」查看请求记录）。
2. **TLS 配置**（仅启用 HTTPS 时出现）：按上面选好的证书来源填写。
3. **上游服务器**：点「添加上游」，填后端真实服务的**主机地址**（IP 或域名）、**端口**、**协议**（HTTP/HTTPS）；多台上游用「权重 %」分配流量；「回源域名」留空即可（留空=不覆盖，Host 跟随客户端请求或上游地址）。
4. **高级选项**：新手全部保持默认。
5. **预览保存**：核对无误后点「保存规则」。

保存后面板会把新配置即时应用到内置 Caddy（事务内应用 + 自动重载，无需手动重载；校验不过不落库，失败会明确报 400，数据库与运行配置不会不一致）。

## 第四步 · 试一个 TLS 透传（可选）

TLS 透传 = 把某个域名的 HTTPS 流量**原样字节转发**给上游服务器，TLS 握手在上游完成（适合上游已经自带证书、自己管证书的场景）：

1. 新建规则，协议选 **TLS 透传**；
2. **SNI 域名**：填单个域名，支持 `*.example.com` 通配（`*` 只能占最左标签）；不支持 IP 字面量（Layer4 按握手里的 SNI 域名分流）；
3. 监听端口：固定为部署侧 HTTPS 默认口（默认 443，向导中只读）；
4. **上游地址**：`host:port` 形态（如 `10.0.0.5:10443` 或 `[2001:db8::1]:10443`），上游自带反向代理与证书；
5. 保存。面板会提示两条须知：**证书由上游管理**（本系统不申请、不续期、不监控有效期）；**透传域名不支持 HTTP/3**（自动降级 HTTP/2/1.1）。

> **443 端口会由 Layer4 接管**：启用透传规则后，443/TCP 由内置 Caddy Layer4 按 SNI 域名分流——命中透传域名的流量原样转发给上游，**其余流量（包括你已有的普通 HTTPS 规则）走兜底路由继续本地终结**，同端口透传/终结可共存、并发互不影响（已由真实进程 spike T-4 实证）。所以现有的 443 HTTPS 规则不需要任何改动。

## 第五步 · 验证

- **浏览器**：访问 `https://你的域名`（DNS 已指向本服务器），能打开后端服务的页面即成功；
- **命令行**：
  ```bash
  curl -I http://你的域名       # HTTP 规则（开了 HTTPS 重定向会返回 301）
  curl -skI https://你的域名    # HTTPS 规则（-k 跳过证书校验，自签/未信任证书时用）
  ```
- **面板**：「负载均衡」列表看该规则的启用开关与状态；开启过访问日志的规则可点行内「日志」按钮看请求记录；
- **容器日志**：`docker logs lazy-balancer`（加 `-f` 持续观察）。

## 常见问题（FAQ）

**80/443 端口被占用了怎么办？**

启动容器时加环境变量换代理默认口：`-e HTTP_PORT=8080 -e HTTPS_PORT=8443`（host 网络下这就是 Caddy 实际绑定的端口）。注意这两个值只决定「默认语义」（新建规则的默认端口、兜底站、跳转判定），**已保存规则的端口不会自动迁移**，需要在面板逐条修改后保存。管理面板口 8000 在容器形态固定不可改（改了会让内置健康检查打错端口）。详见[部署指南](deployment.zh-CN.md)。

**我用的是 Docker Desktop（macOS/Windows），有什么要注意的？**

用 bridge 模式 + `-p` 端口映射（见前置要求），`/app/data` 用 named volume（`lb-data`）而不是 bind mount——bind mount 经 FUSE 共享层有 SQLite WAL 丢页风险。仓库 `docker-compose.yml` 的主节点固定 host 网络，仅适用于 Linux 场景。

**证书怎么管理？**

- 本地终结的 HTTPS 规则（普通规则）：手动上传证书、ACME + DNS 自动签发续签（需先在「系统设置 / 免费证书」配置 DNS 提供商）、或引用 `/app/certs` 目录内的证书文件（外部更新文件后自动同步重载）三选一；
- TLS 透传规则：证书完全由上游服务器管理，本系统不申请、不续期、不监控有效期。

**出问题先看哪里？**

1. 面板「负载均衡」页：规则是否启用；行内「日志」按钮（需规则开启访问日志）看请求记录；
2. 容器日志：`docker logs lazy-balancer`；
3. 容器健康状态：`docker ps`（镜像自带健康检查；冷启动含规则回放与证书物化，90 秒启动宽限期内显示 starting 属正常）；
4. 保存规则报 400：按提示修改即可——校验不过不落库，不会出现「存了一半」的状态。
